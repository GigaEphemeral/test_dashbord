# 故障注入功能说明（容器故障 / 线程故障 / OOM）

> 入口：实时监控与操作 → 右下角「故障注入」「线程工具」抽屉。
> 本文说明每个动作到底改什么、作用在哪个线程/进程、如何恢复，以及为什么 OOM 默认被拒绝。

## 1. 两类故障不要混用

| 类型 | 作用对象 | 入口 | 典型效果 |
|---|---|---|---|
| 容器故障 | 整个容器 / 整个 JVM 进程 | 故障注入抽屉 | 实例下线、请求 502/超时、健康检查失败 |
| 线程故障 | 目标实例 JVM 内的**演示线程** | 线程工具抽屉 | 线程状态、CPU、堆、线程数、队列指标变化；不直接杀业务线程 |

容器故障不是“注入到某个线程”，它直接操作 Docker 容器；线程故障不是“操作 Tomcat 业务线程”，它创建并驱动专门命名的演示线程。

## 2. 容器故障

### 2.1 目标名称

控制台下拉显示 `app-1 / app-2 / app-3`；服务端会规范化为容器名 `jl-app-1 / jl-app-2 / jl-app-3` 再执行。
直接调用 API 时两种写法都接受：

```text
POST /lab-api/chaos/instances/app-1/actions
POST /lab-api/chaos/instances/jl-app-1/actions
```

（此前的 `40401 Container not found: app-1` 就是只传了实例名没有映射到容器名，已修复。）

### 2.2 动作

| 动作 | 实际行为 | 自动恢复（TTL） | 典型观测 |
|---|---|---|---|
| `kill` | `docker stop` 目标容器 | 到期 `docker start` | 该实例请求失败/被 Nginx 摘除；容器停止；`up=0` |
| `freeze` | 向容器主进程发 `SIGSTOP` | 到期 `SIGCONT` | 进程冻结、健康检查超时、请求挂起/超时；容器仍 running |
| `restart` | 重启容器（一次性） | 无 | 短暂下线后恢复；JVM 重新启动 |
| `start` | 启动一个已停止容器 | 无（一次性） | 实例恢复 |
| `resume` | 对冻结容器发 `SIGCONT` | 无（一次性） | 冻结解除 |

- TTL 默认 60s，最大 600s；`kill/freeze` 到期自动回滚。
- 向导暂停时 TTL 冻结，但「全部停止」仍可清理。
- `kill` 会中断正在处理的请求；正在跑的 k6 会看到错误/超时，正式对照实验不要同时注入。
- 数据类容器（mysql/redis/rabbit 等）受 `chaos.datastore.allowed-target-pattern` 白名单限制，默认拒绝；MySQL 探针容器额外受保护，不能对它 kill/freeze/restart。
- API 可能返回 202 `PENDING_CONFIRMATION`；控制台会轮询 operation 到 `APPLIED/RESTORED/FAILED`。“已请求”不等于“已生效”。

### 2.3 推荐演示

1. 先看监控页三实例 RPS/P95 和拓扑；
2. `kill app-1`，TTL 60s；看 Nginx 分流、app-1 指标消失、错误率；
3. 到期自动 start，确认健康恢复；
4. 再用 `freeze app-2` 看“容器在跑但进程不响应”的差异；
5. 最后「清除全部故障」/ stop-all 收尾。

## 3. 线程故障（线程工具抽屉）

> **JDK8 槽位限制（app-3）**：app-3 已承接全部业务流量与缓存实验，但 `/lab/thread/**`
> 尚未移植到 Boot 2.7 外壳，因此线程工具选择 app-3 时控制台会直接提示不可用、不再发出 404 请求；
> 容器故障（`kill` / `freeze` / `restart`）对 app-3 完全可用。线程实验室的 JDK8 版本
> （虚拟线程模式除外）列为后续项，见 `step-S2-B5-05e-app3-jdk8-parity.md`。


线程故障只影响**所选实例**；每个模式在目标 JVM 里创建自己的 daemon 线程，线程名前缀为
`thread-lab-<mode>-*`（starvation 的池线程为 `thread-lab-starvation-*`，thread-leak 为
`thread-lab-thread-leak-*`）。它们不会去改 Tomcat `http-nio-*` 或业务线程池里的线程。

| 模式 | 创建的线程 / 行为 | 主要观测 |
|---|---|---|
| `deadlock` | 两个 worker 以相反顺序抢两把 monitor；默认每轮释放第一把，保证 stop 可回收；奇偶线程有半周期错相，确保能观测到 `BLOCKED` | 线程状态 BLOCKED；`jstack` 锁竞争 |
| `stuck` | 多个 worker 停在一个永不打开的 latch 上 | WAITING/TIMED_WAITING；线程数上升 |
| `cpu-burn` | worker 空转计算，定期 `Thread.yield()` | `process_cpu_usage` 上升、RUNNABLE |
| `heap-leak` | 按固定间隔分配且有硬上限，不会把共享 JVM 推到 OOM | 堆阶梯上升后走平；GC 次数/停顿 |
| `oom` | 无上限分配，直到 JVM `ExitOnOutOfMemoryError` 退出 | 堆断崖、进程退出；**默认拒绝** |
| `thread-leak` | 持续创建平台线程（JDK21 可选虚拟线程），有存活上限 | 活线程数持续上升 |
| `starvation` | 一个小线程池 + 有界队列，提交大量阻塞任务 | 池 active=max、队列增长 |

### 3.1 保持方式

- `auto`：TTL 秒数到点自动停止；TTL 1–600s。
- `manual`：不自动回退；演示结束必须点「全部停止」。
- `暂停`只冻结该动作的 TTL 倒计时，不停止参与线程；`继续`恢复倒计时。
- `停止`会中断/回收线程并注销指标；同一模式重复注入返回 409。

### 3.2 单线程生命周期

「单线程生命周期」是另一组独立 API：真实创建一条名为 `thread-lab-demo` 的线程，推进 NEW →
RUNNABLE → BLOCKED/WAITING → TIMED_WAITING → TERMINATED；`冻结并抓快照`只暂停推进并抓取
jstack/堆信息，不冻结整个 JVM。它和上面的故障模式互不影响。

### 3.3 线程快照

「抓取快照」执行 `jcmd Thread.print` / `GC.heap_info` / class histogram，写入宿主机
`doc/process/Stage1/snapshots/` 并尽力打 Grafana annotation。抓取失败仍返回 200，但
`captured=false`；以返回字段为准。

## 4. 为什么 OOM 默认被拒绝

`oom` 是**无上限分配**，会让目标 JVM 真正 OOM 并退出。当前 app-1/2/3 是共享业务实例，
所以服务端默认：

```text
app.lab.thread.oom.throwaway-instance = false
```

此时请求返回：

```text
400（40001）：Mode 'oom' is refused: it needs app.lab.thread.oom.throwaway-instance=true
```

要在**一次性、小堆、无人使用**的实例上演示 OOM：

1. 准备一个独立的 throwaway 实例（不要用 app-1/2/3 共享节点），设置较小 `-Xmx`（如 128–256m）；
2. 在该实例环境设置 `LAB_THREAD_OOM_THROWAWAY=true`（映射到 `app.lab.thread.oom.throwaway-instance`）；
3. 重启该实例；
4. 注入 `oom`，观察堆断崖、`ExitOnOutOfMemoryError` 和容器退出；
5. 该实例会被重启策略拉起，不能依赖 TTL 恢复 JVM。

共享节点上不要打开这个开关；`heap-leak` 已提供有上限的堆增长演示，不需要 OOM。

## 5. 与实验 run 的关系

- 容器故障可通过 `runId` 写入 run 的故障时间线；不传则不关联。
- 线程故障由 app 侧 `/lab/thread/**` 管理，控制台通过 `/lab-api/chaos/app/{instance}/lab/thread/**` 代理；
  可在 run 期间观察指标，但正式压测对照建议一次只引入一个变量。
- `stop-all` 会清理容器故障、Toxiproxy、背景流量、线程故障和 k6 容器；但 RUNNING run 仍需要手动 stop。

## 6. 安全边界

- 只允许 `lab=java-learn` 白名单容器；
- 数据类目标默认拒绝，MySQL 探针容器受保护；
- `kill/freeze/restart` 需要明确目标与 TTL，操作落 `lab_operation`；
- 线程故障有线程数/堆上限，OOM 另需显式一次性实例开关；
- 演示结束请「清除全部故障」，并确认实例健康、线程故障列表为空。
