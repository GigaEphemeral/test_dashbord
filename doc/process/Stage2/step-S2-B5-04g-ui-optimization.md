# 设计逻辑

- **单一配置源不变**：向导第 3 步仍读写 `lab_instance_config`；创建 run 时服务端按 nodes 快照配置，浏览器不参与竞态。
- **实例卡片只读**：卡片不提供保存/应用，只提供“线程工具 / JVM 参数”跳转；“JVM 参数”会切到向导第 3 步并滚动到对应实例列。
- **拓扑语义修正**：`enabled=false` 只对 Java 槽位表示“未启用”；Redis/MySQL/Router 是运行中应用的依赖，不再因为不在 run 的 toggle 集合而被灰化或断开连线。
- **L1 关闭的指标事实**：后端在 L1 关闭时**不递增** `cache_l1_requests`（`TwoLevelCache` 注释与实现），因此前端不能画 0 命中率，必须显示“不适用”并把流量改道到 L2。
- **JDK8 边界**：`seckill-app-jdk8` 是 Boot 2.7 独立模块，只覆盖读路径/Actuator/快照；不能替换 app 槽位（缺 `/api/login`、缓存实验室、开关等），因此只做“对照外壳”配置与观测（JVM 参数表第 4 行）。
- **抽屉可共存**：抽屉打开时监控页仍可见/可滚动；Esc 关闭，body 滚动锁在关闭/卸载时释放。
