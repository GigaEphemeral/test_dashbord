# B5-03 单次实验统计与导出（替代“重复 N 次”）

> 版本：v1（2026-10-29 用户确认）
> 关联：计划 §6 B5-03、验收 A32；B5-02 分流口径；B5-04b summary 解析
> 结论：**不做重复组编排**。人工多次执行，每次结果完整统计并导出 JSON，事后人工比较。

## 1. 目标与边界

**目标**

- 单次 run 的全部可比数据收敛为一个“本次结果”视图，并能一键导出 JSON。
- 让“改一轮配置 → 跑一次 → 导出 → 人工对比”成为稳定操作。
- 顺手修正实时监控图表的三处可读性问题（JVM 拆图、GC 类型、池按实例）。

**不做**

- 重复组、自动顺序执行、自动中位数/离散度、自动对比报表。
- d7 矩阵模板（移入 Future）。
- 新增指标采集；全部复用现有 Prometheus/summary/台账数据。

## 2. 实时监控图表改造（B5-01c）

| 图 | 现状 | 改后 |
|---|---|---|
| 请求性能 | 聚合三条 | 不变 |
| k6 负载 | 聚合两条 | 不变 |
| JVM 堆 / GC | 堆与 GC 同轴，区分度低 | 拆成 **JVM 堆（按实例）** 与 **GC（按实例·类型）** |
| 线程池 / 连接池 | 四条聚合 | 拆成 **业务线程池（按实例）** 与 **连接池（按实例）** |

- GC 类型按 `action` 标签二分：`end of minor GC`（实线）/ `end of major GC`（虚线）；颜色按实例；采集器名（G1/Copy/MarkSweepCompact）进 tooltip。
- GC 曲线取“次/分钟”：`sum by (instance, action) (increase(jvm_gc_pause_seconds_count{job="seckill-app"}[1m]))`。
- 线程池：`executor_active_threads` 实线 + `executor_queued_tasks` 虚线，按实例分色。
- 连接池：`hikaricp_connections_active` 实线 + `hikaricp_connections_pending` 虚线，按实例分色。
- 抽共享组件 `TimelineChart.vue`：输入多图配置（标题、序列、因子、格式化、分割维度），输出 SVG；`MonitorTimeline` 与 run 时间线共用。

## 3. 实验记录页 run 时间线

选中 run 后展示，窗口 = `startedAt..endedAt`（进行中取 now），步长 `max(15s, duration/300)`，最多 300 点：

1. k6 压力：`sum(k6_vus{run_id="$run"})`、`sum(rate(k6_iterations_total{run_id="$run"}[1m]))`；
2. JVM 堆：`sum by (instance) (jvm_memory_used_bytes{job="seckill-app",area="heap"})`；
3. GC 次数：`sum by (instance, action) (increase(jvm_gc_pause_seconds_count{job="seckill-app"}[1m]))`。

无序列 → “无数据”；窗口未开始 → 提示先启动 run。

## 4. 单次结果报告

### 4.1 端点

| 端点 | 说明 |
|---|---|
| `GET /lab/runs/{runId}/report` | 内联 JSON（面板渲染用） |
| `GET /lab/runs/{runId}/export` | 同一内容，`Content-Disposition: attachment; filename=run-<runId>-report.json` |
| `POST /lab/runs/{runId}/clone` | 复制 params/config/nodes/故障时间线为新 DRAFT，名称加 `(copy)` |

- 报告查询对 metrics 走**只读**路径，不写 `lab_metric_window`。
- 模板处于 RUNNING/VALIDATING/READY/UNKNOWN 时 clone 返回 409；run 不存在 404。

### 4.2 JSON 结构

```json
{
  "meta": {
    "reportVersion": 1,
    "generatedAt": "2026-10-29T13:40:00Z",
    "repeatVerified": false,
    "note": "单次结果为演示性数据，未重复验证"
  },
  "run": {"runId":"...","name":"...","scenario":"load","nodes":["app-1"],"status":"COMPLETED",
          "startedAt":"...","endedAt":"...","durationSeconds":120,"trafficMode":"via-nginx","targetInstance":null},
  "environment": [
    {"instance":"app-1","imageTag":"jdk21","imageId":"sha256:...","javaVersion":"21.0.x",
     "jvmArgs":{...},"gc":{...},"configRevision":27,"configStatus":"APPLIED","capturedAt":"..."}
  ],
  "k6": {
    "available": true,
    "requests": 188168, "iterations": 187668, "vusMax": 500,
    "rps": 313.1, "failedRate": 0.1341,
    "durationMs": {"avg":120.1,"med":38.0,"p95":404.9,"p99":1686.2},
    "thresholds": [{"metric":"flow_errors","condition":"rate<0.01","passed":false}],
    "note": null
  },
  "instances": {"quality":"OK","note":"...","upstream":{...},"rows":[ ... B5-02 InstanceRow ... ]},
  "kpi": {"quality":"OK","window":{...},"metrics":[ ... MetricView ... ]},
  "quality": {"k6Report":"OK","metrics":"OK","missing":["app-3 config"]}
}
```

缺省规则：没有 summary → `k6.available=false` + `quality.k6Report=NO_SUMMARY`；没有序列 → 对应字段 `null`；任何缺项都写入 `quality.missing`，不补 0。

### 4.3 数据来源

| 段 | 来源 |
|---|---|
| run | `RunLedgerRepository.findRun` + `findParams`（traffic mode/target） |
| environment | `lab_run_env`（起跑时抓取）+ `lab_instance_config`（revision/status） |
| k6 | `BenchRunExecutor.report(runId)` 的 summary.json（扩展解析） |
| instances | `InstanceStatsService.query(runId)`（B5-02） |
| kpi | `MetricsService.queryRun` 只读模式（13 个目录键） |
