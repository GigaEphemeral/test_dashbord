# 安装与打包手册

> 面向**第一次在这台机器上把实验室跑起来**的人：从零到 `verify.sh` 全绿需要装什么、构建什么、按什么顺序启动、每步怎么验证、失败怎么排。
> 本文只讲「怎么装、怎么打包、怎么起、怎么验」；**每个实验怎么演示**在 [`doc/readme.md`](../readme.md) §4，**为什么这么设计**在 [`doc/design/details/`](details/)。
> 所有命令都在仓库根 `D:\000CODE\JAVA-LEARN` 下用 **Git Bash** 执行；实测环境为 Windows 10 + Docker Desktop（WSL2 后端）。

## 1. 前置软件

| 软件 | 版本 / 实况 | 用在哪 | 缺了会怎样 |
|---|---|---|---|
| Docker Desktop（WSL2） | 需给 Docker 至少 **12GB** 内存 | 全部容器 | 什么都跑不了 |
| Git + Git Bash | 仓库自带 `.gitattributes` 强制 `*.sh`/`*.tpl` 为 LF | 所有脚本入口 | Windows 下用 PowerShell 跑 `.sh` 会失败 |
| JDK 21 | PATH 上是 21 | 宿主机跑 `mvn test` | 宿主机测试跑不了（**镜像构建不需要宿主机 JDK**，见 §5） |
| Maven 3.9.x | 本机实际运行在 JDK 25（`D:\env\jdk\25.0.3`） | 宿主机测试 / 打包 | 同上 |
| Node.js + npm | 实测 Node v22/v24 均可 | 操作台前端构建、k6 单测、docclaims 校验、console-smoke | `up.sh` 直接报错退出（它必须构建前端 dist） |
| curl | 宿主机侧 | 打 `127.0.0.1:8080` 的 `/api/**`、`/lab-api/**`、`/prom/**` | 宿主机侧演示命令跑不了 |
| Python 3 | 可选 | 只用于个别排查脚本 | 不影响安装 |

**不需要**在宿主机装：k6（用固定镜像 `grafana/k6:1.3.0` 跑）、MySQL/Redis/Nginx/Grafana/Prometheus（全部容器化）、JDK 8（JDK 8 外壳在容器里运行）。

本机实况备注：宿主机只有 **JRE 8**（`C:\Program Files\Java\jre1.8.0_503`），所以 JDK 8 外壳用 `--release 8` 交叉编译、在容器里运行；宿主机侧没有 `jvm_info` 之类的 JDK 8 工具，做双 JDK 对比时一律进容器。

### 端口占用

| 端口 | 用途 | 绑定 |
|---|---|---|
| 8080 | Nginx 入口（业务 API + 操作台 + `/lab-api` 控制面 + `/prom` 代理） | 127.0.0.1 |
| 3000 | Grafana | 127.0.0.1 |
| 15672 | RabbitMQ 管理台 | 127.0.0.1 |
| 6446 / 6447 | MySQL Router 读/写（仅 `db-ha`） | 127.0.0.1 |

启动前确认这些端口没被别的服务占着；Prometheus、chaos-controller、Tempo **不发布宿主端口**，一律经 Nginx 的 `/prom`、`/lab-api` 访问。

## 2. 获取代码与目录约定

```bash
git clone <repo> JAVA-LEARN && cd JAVA-LEARN
git checkout feature/ha-lab
```

```
code/                     全部可运行代码
  pom.xml                 Maven reactor（7 个模块，见 §5.1）
  platform/               platform-common、platform-observability
  services/               seckill-core、seckill-lab、seckill-app-jdk21、seckill-app-jdk8、chaos-controller
  lab/
    docker/               compose 分层 + Nginx/Prometheus/Grafana/MySQL/Redis 配置
    scripts/              up/down/verify/smoke/reset/bench/db-ha-* 等入口脚本
    k6/                   压测场景、运行器、单测、报告归档
    dashboard/            Vue 3 操作台（构建产物 dist/ 挂进 Nginx，已 gitignore）
    scenarios/            故障场景 JSON（schema v1）
    docclaims/            文档断言登记表（机检，见 §7）
doc/                      design（总体设计 + details 细节设计）、process（每步交接）、避坑、readme
```

**换行符**：仓库是混合的。`*.sh`、`*.tpl`、`compose.toxiproxy.yml` 由 `.gitattributes` 强制 LF；`code/lab/docker/grafana/dashboards/*.json` 与 `code/lab/docclaims/claims.yml` 在 git blob 里是 **CRLF**（`core.autocrlf=false`）。用会重写换行符的编辑器改这两类文件，会产生「整文件 diff」，评审时看不出真实改动——改前先确认编辑器的行尾设置。**踩过的实例**：`doc/process/阶段交接-2026-10-26.md` 前 447 行 CRLF、其后追加的批次段落是 LF；用整文件重写型编辑器改尾部一行，会把 184 行 LF 全刷成 CRLF（`git diff --stat` 显示 185 insert / 184 delete，而真实改动只有 4 行）。修法：按字节读入、`rstrip("\r")` 后前 447 行补 `\r\n`、其余补 `\n` 再写回。审计行尾必须用二进制读（文本模式会把 `\r\n` 翻译成 `\n`，虚报「0 个 CRLF」）。

## 3. 配置 `.env`（唯一的手工步骤）

```bash
cp code/lab/docker/.env.example code/lab/docker/.env
```

`.env` **不提交**（已 gitignore），token 与口令只放在那里。要用 MySQL InnoDB Cluster 还要看 `code/lab/docker/.env.example` 之外的 `code/lab/docker/.env.mysql.example`（Router 镜像、SSL、集群引导参数）。

必须按自己的机器改的键：

| 键 | 为什么要改 |
|---|---|
| `LAB_TOKEN` | 所有 `/lab/**`、`/lab-api/**` 的 `X-Lab-Token`；示例值不可用于任何暴露场景 |
| `GRAFANA_ADMIN_USER` / `GRAFANA_ADMIN_PASSWORD` | Grafana 登录；`verify.sh` 也从这里读凭据 |
| `MYSQL_ROOT_PASSWORD` / `MYSQL_PASSWORD` / `MYSQL_USER` / `MYSQL_DATABASE` | 单机 MySQL |
| `RABBITMQ_DEFAULT_USER` / `RABBITMQ_DEFAULT_PASS` | RabbitMQ |
| `REDIS_HA_PASSWORD` / `REDIS_HA_*_IP` / `REDIS_HA_SUBNET` | 仅 `--profile ha`；Sentinel **必须用固定 IP** monitor，用主机名会 `#tilt`（见 [避坑 05](../避坑/05-sentinel-hostname-monitor.md)） |
| `CHAOS_GUIDE_TARGET_PATTERN` / `CHAOS_DATASTORE_ALLOWED_TARGET_PATTERN` | 故障目标白名单，**空 = 全拒**；要杀 MySQL 节点必须显式放开 `^jl-mysql-[0-9]+$`（见 [避坑 09](../避坑/09-chaos-allowlist.md)） |
| `MYSQL_MODE` / `DB_WRITE_URL` / `DB_READ_URL` | `standalone`（默认）或 `router`；改了要重建 app 层并 reload Nginx |

其余键（`*_IMAGE`、`LAB_TOGGLE_*`、`SMOKE_*`、`TOXIPROXY_*`、`OTEL_AGENT_VERSION`、`TZ` 等）用模板默认值即可，全部是可外置的运行时参数——**不要在代码里硬编码这些值**（工程规约要求）。

> `up.sh` 会逐个列出缺失的 env 键名并退出，不会静默用空值。嵌套默认值 `${A:-x:${B}}` 在 B 未定义时会渲染成空串且不报错，这是踩过的坑（[避坑 07](../避坑/07-compose-nested-defaults.md)）。

| 采集 | `otel/opentelemetry-collector-contrib:0.116.1` | `d0ebf65280da` |

拉全部镜像：

```bash

  --env-file code/lab/docker/.env \
  -f code/lab/docker/compose.base.yml -f code/lab/docker/compose.dev.yml \
  -f code/lab/docker/compose.ha.yml -f code/lab/docker/compose.mysql.yml \
  -f code/lab/docker/compose.toxiproxy.yml \
  --profile ha --profile db-ha --profile chaos-proxy --profile dual-jdk pull
```

### 4.2 构建型镜像（3 个，多阶段）

| 镜像 tag | Dockerfile | 运行基础镜像 | 谁用 |
|---|---|---|---|
| `java-learn-lab/seckill-app:jdk21` | `code/services/seckill-app-jdk21/Dockerfile` | `eclipse-temurin:21-jdk-alpine` | `app-1/2/3`（常驻） |
| `java-learn-lab/seckill-app:jdk8` | `code/services/seckill-app-jdk8/Dockerfile` | `eclipse-temurin:8-jdk-alpine` | 仅 `--profile dual-jdk` |
| `java-learn-lab/chaos-controller:jdk21` | `code/services/chaos-controller/Dockerfile` | `eclipse-temurin:21-jre-alpine` | `jl-chaos-controller` |

三个 Dockerfile 的共同结构：

1. **build 阶段** `FROM maven:3.9-eclipse-temurin-21`，构建上下文是 `code/`（reactor 根），只 `COPY pom.xml platform services`，然后
   `mvn -q -pl <模块> -am -DskipTests package`——所以**宿主机不需要装 Maven/JDK 也能出镜像**。
2. build 阶段还会 `curl` 下载 **OTel javaagent**（`OTEL_AGENT_VERSION`，默认 2.10.0）到 `/opt/`，并 `test -s` 校验非空：**构建期必须有到 `repo1.maven.org` 的网络**，下载失败直接让构建失败（链路是必需项，不做降级）。
3. **runtime 阶段**建 `app` 用户并以 `USER app` 运行，`ENTRYPOINT` 固定带
   `-javaagent:/app/otel/opentelemetry-javaagent.jar -XX:MaxRAMPercentage=70 -XX:+ExitOnOutOfMemoryError`。

两个 app 镜像刻意用 **JDK 而不是 JRE**：线程实验室的快照要在容器内跑 `jcmd Thread.print -l`、`GC.heap_info`、`GC.class_histogram`（JDK 8 侧是 `jstack`/`jmap -histo`）。代价是体积（JDK 21 侧约 +180MB，JDK 8 侧 469MB→521MB），本地实验室接受。

**运行镜像里没有 `curl`、也没有 `bash`**（Alpine + BusyBox），容器内只能用 `wget`；详见 [避坑 16](../避坑/16-app-image-has-no-curl.md)。

## 5. 打包与构建

### 5.1 宿主机 Maven（只为跑测试，不出镜像）

```bash
mvn -f code/pom.xml test                       # 全量单测/集成测试
mvn -f code/pom.xml -DskipTests package        # 只想拿 jar 时
```

reactor 7 个模块：`platform/platform-common`、`platform/platform-observability`、`services/seckill-core`、`services/seckill-lab`、`services/seckill-app-jdk21`、`services/seckill-app-jdk8`、`services/chaos-controller`。
`java.version=21`、`maven.compiler.release=21`；`platform-common` 与 `seckill-core` 用 `--release 8` 编译，好让 JDK 8 外壳复用同一份领域代码。

### 5.2 构建三张应用镜像

```bash
# dev 栈用的两张（app + 控制器）
docker compose --project-name java-learn-lab --project-directory code/lab/docker \
  --env-file code/lab/docker/.env \
  -f code/lab/docker/compose.base.yml -f code/lab/docker/compose.dev.yml \
  build app-1 chaos-controller

# JDK 8 外壳（定义在 compose.base.yml 的 dual-jdk profile 后面）
docker compose --project-name java-learn-lab --project-directory code/lab/docker \
  --env-file code/lab/docker/.env \
  -f code/lab/docker/compose.base.yml -f code/lab/docker/compose.dev.yml \
  --profile dual-jdk build app-jdk8
```

`app-1/2/3` 共用同一个 `image:` tag，构建一次即可（`up -d` 时另两个实例直接复用）。

`up.sh` 只执行 `compose up -d --wait --wait-timeout 240`，**没有显式 build 步骤**；三个服务都带 `build:` 段，镜像缺失时 Compose 会自行构建，但首次安装建议按上面显式跑一次——这样构建失败不会混在启动流程里，也方便单独计时。

**实测（2026-10-27，仓库根冷构建，两条 `docker compose build` 连跑）**：总墙钟 **3m37.719s**；其中 app-1 的 `mvn -pl seckill-app-jdk21 -am -DskipTests package` **180.2s**、chaos-controller **140.7s**、OTel javaagent 下载 **3.8s**。产物与当前实况：

| 镜像 | tag → image ID | 体积 | 备注 |
|---|---|---|---|
| 应用 JDK 21 | `java-learn-lab/seckill-app:jdk21` → `cfb7a164e9b3` | 940MB | 更早的备份位 `:jdk21-pre-d10` 是 674MB；两份差 266MB，本轮没有逐项拆分归因（层缓存、运行时与快照工具链都可能参与），只作体积实况记录 |
| 应用 JDK 8 | `java-learn-lab/seckill-app:jdk8` → `ae47291781fe` | 481MB | 运行时 `eclipse-temurin:8-jdk-alpine`，为的是容器内能跑 `jstack`/`jcmd`/`jmap` |
| 控制器 | `java-learn-lab/chaos-controller:jdk21` → `409a4e944856` | 398MB | 运行阶段是 JRE |
| 回滚位 | `:jdk21-pre-docs` → `694d4586c398`、`:jdk21-pre-d10` → `699fa18fd18d`、`chaos-controller:jdk21-pre-docs` → `9ac92f049bc7` | — | 本文档整理这一批构建前打的备份 tag |

> **Compose 只认 tag，不比对 image ID**：本轮重建后 `:jdk21` 已指向 `cfb7a164e9b3`，但 `jl-app-1/2/3` 三个**运行中的容器仍指向 `694d4586c398`**（即 `:jdk21-pre-docs`）——`docker inspect jl-app-1 --format '{{.Image}}'` 可复核。要让文档里的镜像与线上容器一致，需要 `up -d --force-recreate app-1 app-2 app-3`；这条也登记在 `doc/design/details/README.md` §3.2。

### 5.3 操作台前端

`code/lab/dashboard/dist/` 已 gitignore，`up.sh` 会在 dist 缺失或比源码旧时自动执行：

```bash
cd code/lab/dashboard && npm ci --no-audit --no-fund && npm run build
```

要求 `package-lock.json` 存在（保证可复现）；缺 npm 或缺 lock 文件时 `up.sh` 直接报错退出，不会挂一个空目录进 Nginx。

## 6. 启动

### 6.1 profile 矩阵

`up.sh` **一次只接受一个 profile**（传组合会报错）：

| 命令 | 叠加的 compose 文件 | 用途 |
|---|---|---|
| `bash code/lab/scripts/up.sh --profile dev` | base + dev | 日常：单机 MySQL/Redis + 三实例 + 观测栈 |
| `bash code/lab/scripts/up.sh --profile ha` | + `compose.ha.yml` | Redis Sentinel（1 主 2 从 3 哨兵 + exporter） |
| `bash code/lab/scripts/up.sh --profile chaos-proxy` | + `compose.toxiproxy.yml` | 应用经 Toxiproxy 访问 Redis/MySQL（会重建 app 层） |
| `bash code/lab/scripts/up.sh --profile dual-jdk` | base + dev（JDK 8 服务在 base 里带 profile） | 追加 JDK 8 外壳，做 D7 对比 |
| `bash code/lab/scripts/db-ha-up.sh` | + `compose.mysql.yml` | MySQL InnoDB Cluster（3 节点 + Router + exporter + 两个 init job） |

> **`db-ha` 不是 `up.sh` 的 profile**：`up.sh --profile db-ha` 会被显式拒绝并提示改用 `db-ha-up.sh`。集群需要引导顺序（先建组、再引 Router），所以走独立脚本。

`ha` 与 `db-ha` 可以同时开着；此时常驻 lab 容器 **32 个**（两个 db-ha init job 是一次性容器，跑完就退出，不计入常驻）。

### 6.2 首次启动顺序

```bash
# 1) 构建镜像（§5.2）与前端（§5.3，up.sh 会自动做）
# 2) 起 dev 栈
bash code/lab/scripts/up.sh --profile dev
# 3) 自检（默认保留栈运行，约 2–3 分钟）
bash code/lab/scripts/verify.sh
# 4) 全栈冒烟（会真实消耗 product 1 与 20 各 1 件库存）
bash code/lab/scripts/smoke.sh
```

需要高可用实验时再叠：

```bash
bash code/lab/scripts/up.sh --profile ha          # Redis Sentinel
bash code/lab/scripts/db-ha-up.sh                 # MySQL InnoDB Cluster
bash code/lab/scripts/db-cluster-status.sh        # 期望 RESULT: ok
bash code/lab/scripts/sentinel-status.sh          # 只读拓扑
```

### 7.1 `verify.sh` 的口径

- 默认**保留栈运行**；要顺手停栈用 `verify.sh --cleanup`。
- 1 个 **WARN** 是预期的：Docker Desktop/WSL2 下 cAdvisor 拿不到 per-container 序列。
- 会逐个断言 Grafana 里 **10 个面板 uid** 都被 provision（`ha-d1`…`ha-d4`、`ha-d6`…`ha-d11`；`ha-d5` 没有面板文件，链路由 Tempo UI 承担），并额外断言 D10 暴露 `run_id` 模板变量。
- **`REDIS_MODE=sentinel` 期间，verify 的 Redis 内容检查会假失败**（[避坑 11](../避坑/11-verify-vs-redis-mode.md)）；演练完先把 app 层还原 standalone 再跑。
- **PASS 数会随断言新增漂移**：103 → 104（第三批次 JDK8）→ **109**（`8173821` 给 D6/D8/D10/D11 补置备断言）。`verify.sh:931` 的注释还写着「the 97 PASS / 1 WARN baseline」，是注释没跟上，不影响结果（已登记在 `details/README` §3.3）。基线本身由 `8173821` 那条提交的正向断言固定：改面板前先想清楚会不会让这一格漂移。
- **router 模式与 standalone 模式的库存不是一个库**：`MYSQL_MODE=router` 时 `reset-lab.sh` 默认清单机 `jl-mysql`，演练扣掉的库存留在集群里（`RESET_MYSQL_CONTAINER` 显式指定才行）。

### 7.2 文档断言（docclaims）

`code/lab/docclaims/claims.yml` 登记「文档里写死的可机检断言」，`check-doc-claims.mjs` 支持 `file_exists`/`file_contains`/`grep_count`/`shell` 四种；`polarity: negative` 表示「断言某物**不存在**」（此时 `expect: 0` 才合法）。写文档时凡是给了具体数字、路径、命令的，都应该在这里加一条，否则日后必然腐烂。

## 8. 改了代码怎么生效

| 改了什么 | 怎么生效 |
|---|---|
| `code/services/**` Java | `docker compose ... build <service>` 后 `up -d <service>`（或 `up.sh` 重新拉起） |
| `code/lab/docker/grafana/dashboards/*.json` | **不用重启**：文件式 provision，`updateIntervalSeconds: 10`，等十几秒后 `GET /api/dashboards/uid/<uid>` 看 `version` 是否递增 |
| `code/lab/docker/prometheus/*` | 需要重启 `jl-prometheus`（未开 lifecycle reload） |
| Nginx 路由 / `.env` 里的 `MYSQL_MODE` 等 | 重建 app 层 + `docker exec jl-nginx nginx -s reload` |
| `code/lab/dashboard/**` | `npm run build` 后刷新页面（dist 是挂载的静态目录） |
| `code/lab/k6/**` | 不用构建，`run.sh` 每次把目录只读挂进 k6 容器 |
| `code/lab/scenarios/*.json` | 控制器挂载目录，改完 `GET /lab-api/lab/guide/scenarios` 确认 |

重建单个服务（不动数据容器）：

```bash
docker compose --project-name java-learn-lab --project-directory code/lab/docker \
  --env-file code/lab/docker/.env \
  -f code/lab/docker/compose.base.yml -f code/lab/docker/compose.dev.yml \
  up -d --force-recreate app-1 app-2 app-3
```

回滚镜像：构建前先给旧镜像打个备份 tag（例如 `docker tag java-learn-lab/seckill-app:jdk21 java-learn-lab/seckill-app:jdk21-pre-<改动>`），出问题时 tag 回去再 `up -d --force-recreate`。仓库里保留过 `:jdk21-pre-d10` 就是这个用途。

## 9. 停止、重置与清理

```bash
bash code/lab/scripts/reset-lab.sh --dry-run   # 预览要清什么
bash code/lab/scripts/reset-lab.sh --yes       # 停 app → 清订单/库存 → FLUSHDB → 清队列 → 启 app（约 97s）
bash code/lab/scripts/down.sh                  # 停栈，保留命名卷
bash code/lab/scripts/db-ha-down.sh            # 停 MySQL 集群那一层
# bash code/lab/scripts/down.sh --purge        # 危险：删卷，演示数据全丢，非明确要求不要跑
```

两个已知口径：

- **环境重置默认手工**，脚本不会自动清数据；`reset-lab.sh` 默认清的是 standalone 的 `jl-mysql`，`MYSQL_MODE=router` 时集群里的数据它清不到——所以压测会真实扣库存的场景，建议换一个还有库存的 `PRODUCT_ID`。
- 按需/一次性容器（`traffic`、db-ha 的两个 init job、jdk8 外壳）退出后会让操作台状态栏一直 warn，这是预期的；用 `VITE_LAB_ON_DEMAND_CONTAINERS` 调整排除列表。

## 10. 常见安装故障

| 现象 | 根因 | 处理 |
|---|---|---|
| `up.sh` 报缺 env 键 | `.env` 没从模板补齐 | 按提示逐个补键（脚本会列键名） |
| `up.sh` 报 npm / `package-lock.json` 缺失 | 前端 dist 必须可复现构建 | 装 Node，别删 lock 文件 |
| 镜像构建卡在下载 OTel javaagent 后失败 | 构建期需要访问 `repo1.maven.org` | 恢复外网/代理后重试；Dockerfile 有意让下载失败即构建失败 |
| 拉不到 `mysql/mysql-router:8.4.4` | Docker Hub 上没有这个 tag（实际会拉到 8.0） | 用 `container-registry.oracle.com/mysql/community-router:8.4` |
| Router 起来了但 6446 不通 | 8.0 Router 配 8.4 服务器，把三个成员全判 RO 后主动关掉监听 | 换 8.4 Router 并重新引导（`MYSQL_HA_ROUTER_FORCE_BOOTSTRAP=true`） |
| 容器内 `curl: not found` | 运行镜像是 Alpine，只有 BusyBox `wget` | 用 `wget`（[避坑 16](../避坑/16-app-image-has-no-curl.md)） |
| Toxiproxy 容器里 healthcheck/init 跑不了 | 该镜像是 distroless，没有 sh/wget | init 用 `alpine`（[避坑 04](../避坑/04-toxiproxy-distroless.md)） |
| Sentinel 反复 `#tilt` | 用主机名 monitor | 改固定 IP + 跨网段 announce（[避坑 05](../避坑/05-sentinel-hostname-monitor.md)） |
| Prometheus 崩溃循环 `cannot unmarshal !!seq` | 3.0.0 下 `scrape_config_files` 外部文件格式不符 | 改内联 job（[避坑 03](../避坑/03-prometheus-scrape-config-files.md)） |
| 脚本进容器报 `\r` 错误 | CRLF | `.gitattributes` 强制 LF（[避坑 08](../避坑/08-crlf-scripts.md)） |
| 面板某块全空 | 运行中的 app 镜像是旧 jar | 重建镜像 + `up -d --force-recreate` |
| cAdvisor 面板无数据 | Docker Desktop/WSL2 限制 | verify 里已记为 WARN，不必修 |
| Windows 控制台中文乱码 | 控制台是 GBK | 抓输出到文件时显式 UTF-8 |
